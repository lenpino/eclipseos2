SWT Step 025. Menus: dispose and setMenu (null)

Objective

Dispose a menu item with a submenu, and detach a submenu with MenuItem.setMenu (null), without hanging, as MenuManager of JFace does when Eclipse opens an editor. The test case SWT025_01 (22 automatic checks) asks PM about the windows of the menus; its interactive part is a menu bar with nested submenus, detached and set again.

Task notes

  • Eclipse 2.0.1 froze at startup (2026-11-15 to 2026-11-17): the workbench showed, without the text of the Welcome page and with areas not painted, and the user interface never came back. The unpainted areas were the hang, not a defect of painting.
  • The cause: MenuItem.setMenu deleted the item and inserted it again to change it. MM_DELETEITEM destroys the window of the submenu of the item; MM_REMOVEITEM does not. When a submenu is disposed, Menu.releaseChild calls cascade.setMenu (null), so its window was gone when Menu.releaseWidget called getItems (), and getItems looped until MM_ITEMIDFROMPOSITION answered MIT_ERROR: a window that is gone answers 0, for ever, while the array of items grew by 4.
  • Now setMenu uses MM_REMOVEITEM and, for null, takes MIS_SUBMENU and hwndSubMenu away from the item (they were inserted again with the old submenu). getItems and indexOf stop at MM_QUERYITEMCOUNT, so a menu whose window is gone can no longer hang them.
  • How it was found, for the next hang: the guest clock of the VM runs at a fifth of the real speed (VirtualBox gives up catching up), and a busy thread of the user interface starves the other Java threads, so no watchdog based on time or on another thread could report it. The javacore of this JVM (Ctrl+Break) has no stacks of the threads, and suspending a thread from jdb crashes the JVM. The place came from -Xrunhprof:cpu=samples, written at System.exit called by the watchdog: 7 of 33 samples in Menu.getItems, from MenuManager.update in WorkbenchPage.openEditor. DiagMenu then showed PM answering WinIsWindow false and 0 after setMenu (null).
  • Seen on the screen (2026-11-17): Eclipse starts, the Welcome page shows its text, the views (Navigator, Outline, Tasks) and the status bar are painted, and the user interface waits for messages.
