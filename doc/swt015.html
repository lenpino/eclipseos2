SWT Step 015. Cursors

Objective

Implement the o.e.swt.graphics.Cursor class, Control.setCursor() and Tracker.setCursor(). The test case SWT015_01 creates every style, draws the pointers made by SWT into an image and reads its pixels, and sends WM_MOUSEMOVE to the controls to see which pointer they set (72 automatic checks); then it shows a button for each style.

Task notes

  • A cursor is a PM pointer (HPOINTER). The styles that PM has are its system pointers (WinQuerySysPointer without a copy): they belong to PM, are the same for every cursor of that style and are not destroyed by dispose().
  • PM has no hand, cross nor up arrow: they are made by SWT. The hand comes from the data of the Windows source; the cross and the arrow are drawn black with a white border, to be seen on any background.
  • The constructor with ImageData takes, as on Windows, the source as the AND plane and the mask as the XOR plane (transparent: 1, 0; black: 0, 0; white: 0, 1). PM wants both in one monochrome bitmap of double height, made of rows from the bottom: the XOR plane in the lower half and the AND plane in the upper one; the bitmap goes to WinCreatePointerIndirect and is deleted (PM keeps a copy). The hot spot is counted from the bottom too.
  • Control.setCursor() keeps the pointer in hCursor, and findCursor() looks for it in the parents, as on Windows. Windows sets it with WM_SETCURSOR; PM has nothing like it: the default processing of WM_MOUSEMOVE sets the arrow, or the pointer of the native control (the I-beam of an entry field). Control lets that processing run, because the native controls do more work with the mouse, and then sets its cursor. When the cursor is set while the pointer is over the control, it is changed at once.
  • New native WinQueryPointer, used by dispose() (PM is not left showing a pointer that was destroyed) and by the test.
  • The test draws a pointer with WinDrawPointer on the presentation space of a GC and reads it with GpiQueryPel. The first one works in device coordinates and the second one in world coordinates, which the GC turns upside down with its default view matrix: the first run read the picture upside down and the cross seemed one row lower. See lessons learned.

The differences with Windows are in difference 017.
