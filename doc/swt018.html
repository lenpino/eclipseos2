SWT Step 018. Tool tips

Objective

Show the tool tips of the controls (Control.setToolTipText(), which was commented out) and of the tool items. The test case SWT018_01 shows the window, puts the pointer over the controls and reads the window of the tool tip after each wait (23 automatic checks); its interactive part has a button, a text, a label, a canvas and a tool bar with tool tips.

Task notes

  • PM has no tool tip control. The Display shows a window of its own made of static controls: a black rectangle (the border), a light yellow one inside, and a text for each line of the tool tip (a \n gives two lines, as on Windows). It is a child of the desktop, not a Shell: it is not in getShells() and it takes neither the focus nor the activation.
  • The timer of the mouse of step 016 decides when: after 500 ms at rest on a control with a tool tip text it is shown below the pointer (above it when there is no room); it goes away when the pointer leaves the control, when a button or a key is pressed (then it does not come back until the pointer leaves the control) and after 5 seconds. A new text replaces it while it is shown; no text, or the control disposed, takes it away.
  • A ToolItem is a button of its own (step 010): its tool tip text goes to the button.
  • Display.getSystemColor(SWT.COLOR_INFO_BACKGROUND) gave the color of the desktop (SYSCLR_BACKGROUND); now it is the yellow of the tool tips of Windows, 255, 255, 225.
  • A defect of step 016 that the tool tips showed: PM sends WM_MOUSEMOVE to the window under the pointer when a window changes there, also when the pointer does not move (the tool tip that goes away). That restarted the time at rest, so a changed text did not come back and a hover could come late. Now only a move to another position, or to another control, restarts it.
  • The automatic part puts the pointer itself (WinSetPointerPos). In the VM with the integration of the mouse, moving the mouse of the host over the window of the VM puts the pointer back where the mouse is, and the checks fail: the mouse must not be touched until the interactive part, which the test says. A failure says when the pointer is not where the test put it. The same holds for SWT016_01.
  • The window class of the statics is Label.LabelClass (PSZ.getAtom(OS.WC_STATIC)): new PSZ(OS.WC_STATIC) compiles too, because there is a constructor PSZ(int length), and gives an empty buffer.

The differences with Windows are in difference 020.
