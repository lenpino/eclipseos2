SWT Step 021. The Help event

Objective

Send the Help event when the user presses F1, as Windows does: to the control with the focus or, if it has no listener for it, to the first parent that has one, up to its shell; from a menu, to the item that is highlighted or its menu. The test case SWT021_01 posts the key and sends WM_HELP (11 automatic checks); its interactive part has controls, a group and a menu with listeners.

Task notes

  • Control took the listeners, but WM_HELP was left out of its window procedure (the Windows code was there, commented) and no event was ever sent.
  • PM does not make a WM_HELP of an F1 that a program posts (2026-11-13: it arrives as WM_CHAR with VK_F1, and nothing else); the system accelerator table may do it for a real key. So both are taken: Display.filterMessage() sends the event for WM_CHAR of F1 alone, going down and not repeated (KC_PREVDOWN), after the accelerators of the application, and lets the key go on for the KeyDown; Control.WM_HELP() does it for a WM_HELP. Both call Control.sendHelp().
  • WM_HELP: mp1 is the command (the id of the menu item) and mp2 its source and whether the pointer was used. With CMDSRC_MENU the item is found by its id in the shell; a disabled item has no help.
