SWT Step 017. Caret

Objective

Implement the o.e.swt.widgets.Caret class and getCaret()/setCaret() of Canvas. The test case SWT017_01 checks the API, then shows the window, gives the focus to a canvas and reads the text cursor of PM with WinQueryCursorInfo after each change; its interactive part is a box to type in.

Task notes

  • The caret is the text cursor of PM, which belongs to the window that has the focus. Canvas handles WM_SETFOCUS (PM has one message for getting and losing the focus): it creates the cursor with WinCreateCursor when it gets it and destroys it with WinDestroyCursor when it loses it, as the samples of PM do. Moving it is WinCreateCursor with CURSOR_SETPOS; a new size creates it again. It blinks (CURSOR_FLASH) and inverts what is under it (CURSOR_SOLID).
  • WinShowCursor is called only when the state changes; the cursor is created hidden.
  • The y of PM is the lower edge of the cursor, from the bottom of the window: height - (y + cy).
  • New natives WinCreateCursor, WinShowCursor and WinDestroyCursor, and the CURSOR_* constants.
  • The first runs from the SSH session could not take the focus: WinSetFocus failed and no window of the desktop was active (the VM had just been started). After a run from a console of the VM, the same command from SSH took it and passed the 25 checks. When the focus cannot be taken the checks of the focus are skipped and say so. See lessons learned.
  • The first interactive part repainted the whole box after every key (erasing it first), and its text flickered. That was the test, not the caret: the box now paints its own background (NO_BACKGROUND, which the port honours) and repaints only from the changed letter on.
  • Canvas.scroll() is not ported yet; on Windows it hides the caret while it scrolls.
  • Found on the way: Font.equals() compared the FATTRS objects, and Control.getFont() makes a new one each time, so c.getFont().equals(c.getFont()) was false. Fixed afterwards (difference 021).

The differences with Windows are in difference 019.
